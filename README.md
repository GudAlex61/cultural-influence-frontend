# Культурный след — ЛР6

React + TypeScript + Vite + React-Bootstrap, Redux Toolkit, Axios и клиент из Swagger.
Ветка `artwork-excerpts-redux` от исправленной ЛР5 `artwork-excerpts-react`.
Задание: https://github.com/iu5git/Web#лабораторная-6
Методичка кодогенерации: https://github.com/iu5git/Web/tree/main/tutorials/lab7

## Запуск

В первом терминале запустить существующий бэкенд ЛР4 и хранилища:

```powershell
cd C:\Users\Admin\Desktop\cultural-influence-backend
git switch artwork-excerpts-sessions
docker compose up -d
npm ci
npm run build
$env:PORT = '3002'
npm run start:prod
```

База должна быть подготовлена миграциями ЛР4. Для новой БД выполнить `npm run migration:run`.
Не откатывать миграции для восстановления удалённой карточки: удаление логическое.
Второй терминал:

```powershell
cd C:\Users\Admin\Desktop\cultural-influence-frontend
git switch artwork-excerpts-redux
npm ci
npm run dev
```

Открыть **http://localhost:3000/artwork_excerpts**. Использовать везде один хост `localhost`,
в том числе в Postman: cookie для `localhost` не переносится на `127.0.0.1` автоматически.
API работает на 3002, Vite — на 3000, PostgreSQL — 5455, Redis — 6379, MinIO — 9000/9001.
Если эти сервисы уже работают, повторно запускать их не нужно.

## Все четыре страницы

| Страница | URL | Поведение |
|---|---|---|
| Плитка | `/artwork_excerpts` | Опубликованные отрывки, календарь даты создания произведения, кнопки «Найти» и «Сбросить», вертикальная прокрутка. Гость открывает карточку, пользователь может удалить свою. |
| Лента | `/artwork_excerpts/feed` и `/artwork_excerpts/feed/:id` | Первый или выбранный отрывок, одно видео, описание в две строки с раскрытием, дата, цитирования, лайки. «Далее» запрашивает следующий отрывок у сервера. На последнем сервер возвращает первый. Пользователь меняет лайк и удаляет свою запись. |
| Добавление | `/artwork_excerpts/draft` | Только после входа. Первый этап — фото, видео, название; «Далее» загружает оба файла в MinIO и создаёт черновик. Второй — фото и видео, описание, дата создания произведения, количество цитирований; «Опубликовать» завершает запись. Существующий черновик загружается автоматически. |
| Аутентификация | `/users/login` | Вход по логину и паролю; переключение на регистрацию с отображаемым именем. После регистрации выполняется вход. В меню «Вход» меняется на «Выход», появляется добавление. |

Добавление в гостевом меню отключено; прямой переход направляет на вход.
Удалить можно только свою опубликованную запись: интерфейс проверяет `isOwner`,
а сервер независимо проверяет владельца. Регистрация и вход доступны и при наличии старой cookie:
после F5 состояние интерфейса намеренно гостевое.

## Redux и запросы

`src/store/index.ts` создаёт store с reducers `auth` и `artworkExcerpts`.
`configureStore` подключает thunk middleware по умолчанию. Типизированные хуки находятся
в `src/store/hooks.ts`; `Provider` подключён в `src/main.tsx`.

`auth`: пользователь или `null`, загрузка и ошибка.
`artworkExcerpts`: введённая и применённая даты, список, текущая запись, черновик,
источник api/mock, ID просмотревшего, число запросов, ошибка и ID актуальных запросов.
Более ранний ответ списка/ленты не перезаписывает более поздний.
Фильтр сохраняется при переходах между страницами, а «Найти» передаёт его серверу:
`GET /api/artwork_excerpts?artworkCreationDate=1866-01-01`.

Все операции с отрывками реализованы `createAsyncThunk` в
`src/store/artwork-excerpts.slice.ts` через сгенерированный Axios-клиент.
Вход, регистрация и выход — обычный Axios в `src/api/artwork-auth.ts`,
ручной `dispatch`, без thunk и без сгенерированных методов пользователей/сессий.
На время запроса появляется анимация и перекрытие, блокирующее кнопки.

Гость получает mock только при сетевой недоступности сервиса либо HTTP 502/503/504.
Пустой результат, 400, 404 и 500 не подменяются mock. Пользователь при недоступности
видит ошибку; данные mock ему не подставляются. При 401 интерфейс сбрасывает сессию.
В плитке mock отображаются только фото; лента загружает видео одной текущей записи.

Пароль не сохраняется в Redux, localStorage или репозитории. Сессия бэкенда —
HttpOnly-cookie `sessionId`, запись `session:<id>` в Redis. После F5 Redux создаётся заново:
гостевой интерфейс и пустой фильтр, но cookie остаётся в браузере и продолжает отправляться API.
Автоматического восстановления пользователя намеренно нет по порядку показа курса.
При «Выход» сервер удаляет сессию, cookie очищается, Redux и фильтр сбрасываются.

## Два прокси

`vite.config.ts`:

- `/api` → `http://127.0.0.1:3002`, путь сохраняется; ошибка соединения преобразуется в 503.
- `/s3` → `http://127.0.0.1:9000`, префикс `/s3` удаляется.

Браузер обращается к своему origin `http://localhost:3000`. Пример:
`http://localhost:3000/s3/artwork-excerpts/имя-объекта.jpg`.
Фактические имена загружаемых объектов генерирует сервер латиницей.
`artworkMediaUrl` преобразует полученные URL MinIO только при отображении;
URL в БД и DTO остаются исходными. Локальные `/media/...` служат mock/резервными медиа.
Отключать CORS в браузере и добавлять токены в клиентский код не требуется.

## Кодогенерация

```powershell
npm run generate-api
# Без работающего бэкенда — из сохранённой схемы:
npm run generate-api:saved
```

Первый вариант получает настоящий `/api/docs-json`, сохраняет
`documentation/artwork-excerpts.openapi.json` и вызывает `swagger-typescript-api` с
`httpClientType: 'axios'`. Выход — `src/api/generated/ArtworkExcerptsApi.ts`.
Сгенерированный файл вручную не редактируется. Для другого адреса Swagger:
`$env:ARTWORK_OPENAPI_URL='http://localhost:3002/api/docs-json'`.

## Проверка

```powershell
npm run build
npm test
# Требует запущенные Vite, API, PostgreSQL, Redis и MinIO:
npm run test:integration
```

9 проверок состояния покрывают fallback, ошибки, истечение сессии, фильтр,
следующий отрывок, выход, URL медиа и порядок ответов.
Интеграционная проверка создаёт отдельные тестовые аккаунты и собственную карточку,
проверяет загрузку реальных фото/видео через оба прокси, публикацию, одинаковые ключи JSON,
лайк без дублей, отказ удаления чужой карточки, логическое удаление, cookie и выход.
Учётные записи и логически удалённая тестовая запись остаются в БД для проверки;
существующие опубликованные карточки не изменяются.
