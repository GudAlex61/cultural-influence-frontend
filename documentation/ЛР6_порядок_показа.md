# ЛР6 — порядок показа

16 пунктов из README iu5git/Web. Кадры пользователь снимает самостоятельно; дополнительные 6а/6б, 11а/11б и т. п. относятся к исходному пункту, а не меняют порядок.

Общие правила: реальное окно, видимый URL или имя файла, читаемый масштаб; снимок без дорисовок и добавленных шапок. Сохранить PNG вне репозитория в папку `Рабочий стол/РИП6_скриншоты`. В РИП6 заменить соответствующую пустую область фотографией; краткая подпись уже подготовлена.

## 1. Плитка гостя без сервера

Гостевой интерфейс получает учебную коллекцию mock только при недоступном API.

1. Остановить только процесс NestJS на порту 3002; PostgreSQL, Redis, MinIO и Vite оставить работающими. Если сервер запущен в терминале — Ctrl+C. При скрытом процессе сначала найти PID порта 3002 и проверить в Диспетчере задач, что это node с бэкендом, затем завершить этот процесс.

2. Открыть http://localhost:3000/artwork_excerpts и нажать F5. Должны быть карточки, отметка о демонстрационных данных, «Вход» и отключённое добавление. Снять страницу вместе с адресной строкой.

## 2. Лента гостя без сервера

Открывается один отрывок mock с локальным видео и переходом к следующему.

1. При всё ещё остановленном NestJS нажать первую карточку либо открыть http://localhost:3000/artwork_excerpts/feed/1.

2. Снять адресную строку, название, видео, дату, цитирования, лайки и «Далее». Должна быть отметка «Демонстрационный отрывок», а в меню — «Вход». Не показывать авторизованный интерфейс.

## 3. Аутентификация с сервером

Вход выполняется обычным Axios с ручным изменением Redux.

1. Запустить NestJS на 3002: в папке backend выполнить $env:PORT="3002"; npm run start:prod. Открыть http://localhost:3000/users/login.

2. Если своего логина нет, переключиться на регистрацию и создать учебного пользователя. Затем открыть форму входа и снять поля логина и пароля с кнопкой «Войти». Пароль в кадре остаётся скрытым. Войти для следующих кадров.

## 4. Плитка вошедшего пользователя

Плитка получена из БД; меню переключено на «Выход», свои записи имеют кнопку удаления.

1. После входа открыть http://localhost:3000/artwork_excerpts. Для наличия собственной карточки при необходимости сначала выполнить создание и публикацию из пункта 6.

2. Снять плитку с календарём, активным добавлением и «Выход». В кадр включить свою карточку с «Удалить». Нажать «Найти» с датой 01.01.1866 и убедиться, что выдача меняется; фильтр сбросить.

## 5. Лента с сервером

Данные, лайки и следующий отрывок получаются из API.

1. Открыть карточку из плитки. Снять http://localhost:3000/artwork_excerpts/feed/ФАКТИЧЕСКИЙ_ID вместе с названием, тематическими полями, лайком и «Далее».

2. Можно сначала нажать лайк: красная кнопка показывает isLiked=1. В меню должно быть «Выход». Удалять исходные карточки для кадра не нужно.

## 6. Добавление и публикация

Сначала отправляются название и два файла; затем описание, дата и цитирования.

1. Открыть http://localhost:3000/artwork_excerpts/draft. Выбрать фото public/media/crime-and-punishment.jpg, ниже видео public/media/crime-and-punishment.mp4, ввести своё название и снять первый этап с именами файлов.

2. Нажать «Далее». Снять второй этап: фото, видео под фото, описание, дата создания произведения и количество цитирований. Для примера — 01.01.1866 и 166. Затем опубликовать. Для пункта 6 допускаются два снимка, подписи 6а и 6б.

## 7. Изменение записи в PostgreSQL

Число цитирований изменено непосредственно в БД.

1. В терминале выполнить команды ниже. ID 1 — существующий учебный отрывок «Преступление и наказание»; до изменения сохранить исходное citation_count. Сейчас его значение 12840.

2. docker exec cultural_postgres psql -U cultural_user -d cultural_influence -c "SELECT id, artwork_title, citation_count FROM artwork_excerpts WHERE id=1; UPDATE artwork_excerpts SET citation_count=166 WHERE id=1; SELECT id, artwork_title, citation_count FROM artwork_excerpts WHERE id=1;"

3. Снять терминал с самой командой, UPDATE 1 и строкой с 166. Исходное значение потребуется вернуть после кадра 8.

## 8. Изменение БД во фронтенде

Новый запрос показывает 166 цитирований без изменения mock или клиентского кода.

1. Открыть http://localhost:3000/artwork_excerpts/feed/1 и нажать F5. Снять «Преступление и наказание» и число цитирований 166.

2. После снимка вернуть исходное значение: docker exec cultural_postgres psql -U cultural_user -d cultural_influence -c "UPDATE artwork_excerpts SET citation_count=12840 WHERE id=1;". Если перед кадром 7 было другое число, вернуть именно его.

## 9. После F5 Redux гостевой а cookie сохранена

Состояние интерфейса сбрасывается; HttpOnly-cookie sessionId продолжает существовать.

1. Заново войти. В браузере открыть DevTools → Application → Storage → Cookies → http://localhost:3000. При узкой панели вынести DevTools в отдельное окно или увеличить её ширину.

2. Нажать F5. Снять одновременно гостевое меню «Вход» с отключённым добавлением и строку sessionId в Application, включая значение и HttpOnly. Дополнительным кадром 9а до F5 можно показать «Выход». Не выполнять выход перед этим кадром.

## 10. Cookie из браузера в Postman

Тот же идентификатор сессии даёт в API признак владения isOwner=1.

1. Из кадра 9 скопировать значение sessionId. В Postman создать GET с буквальным адресом http://localhost:3000/api/artwork_excerpts. Переменные коллекции не использовать; Params оставить пустым.

2. В Headers добавить Cookie: sessionId=СКОПИРОВАННОЕ_ЗНАЧЕНИЕ (или вставить cookie через менеджер Cookies). Send. В Pretty JSON найти свою опубликованную запись. Снять URL, 200 OK, явный Cookie и id, artworkTitle, isOwner: 1 в ответе. Если срок сессии истёк, войти заново и взять новое значение.

## 11. Состояния Redux

Store содержит auth и artworkExcerpts; фильтр, данные, загрузка и ошибки хранятся в Redux.

1. В VS Code открыть src/store/artwork-excerpts.slice.ts: строки 10–28 — все поля состояния и initialState. Рядом открыть src/store/auth.slice.ts: строки 3–11 — пользователь, загрузка, ошибка и гостевое начальное состояние.

2. Ниже или отдельным кадром 11б показать src/store/index.ts целиком с configureStore и двумя reducers. На снимках нужны имена файлов, номера строк и читаемый код, без терминала и бокового чата.

## 12. Axios в сгенерированном клиенте

HttpClient создан генератором Swagger и использует axios.create.

1. Открыть src/api/generated/ArtworkExcerptsApi.ts. Снять импорт axios около строки 101 и класс HttpClient с constructor и axios.create около строк 143–162. Можно использовать два редактора одного файла рядом.

2. Дополнительным небольшим кадром 12б показать scripts/generate-artwork-api.mjs с generateApi, fileName и httpClientType: axios. Не заменять скрин кодом, набранным в документе.

## 13. Получение отрывков через thunk

Тематический loadArtworkExcerpts вызывает сгенерированный метод и передаёт фильтр даты.

1. Открыть src/store/artwork-excerpts.slice.ts: строки 36–55. Снять createAsyncThunk, filterDate и artworkApi.artworkExcerpts.artworkExcerptsControllerGetPublished; ниже виден fallback только для гостя.

2. При разделении редактора справа показать src/api/generated/ArtworkExcerptsApi.ts около строки 289: GET /api/artwork_excerpts и query. Имена файлов и тематические имена функций должны читаться.

## 14. Создание публикация и лайк через thunk

Методы домена отрывков вызываются внутри createAsyncThunk.

1. В src/store/artwork-excerpts.slice.ts снять строки 85–113: createArtworkDraft, publishArtworkDraft, likeArtworkExcerpt, deleteArtworkExcerpt и вызовы сгенерированного клиента.

2. Если код не помещается читаемо, сделать два кадра 14а/14б. Для пояснения авторизации дополнительно можно показать src/api/artwork-auth.ts: обычный axios.post и dispatch без createAsyncThunk.

## 15. AJAX через прокси в Network

Браузер обращается к своему origin localhost:3000/api; Vite передаёт запрос на порт 3002.

1. Открыть плитку и DevTools → Network, очистить список, выбрать Fetch/XHR. Нажать «Найти» с датой 01.01.1866. Выбрать запрос artwork_excerpts?artworkCreationDate=1866-01-01.

2. Во вкладке Headers снять Request URL http://localhost:3000/api/artwork_excerpts?artworkCreationDate=1866-01-01, Request Method GET и Status Code 200. Фильтр в URL здесь обязателен для проверки; это не переменная коллекции Postman.

## 16. Изображения MinIO через второй прокси

Запросы медиа используют /s3 и реальные имена объектов MinIO.

1. В Network выбрать Img, обновить плитку и выбрать изображение собственной опубликованной карточки из пункта 6. Не брать /media/... — это локальные резервные файлы.

2. Снять имя объекта и Headers: Request URL начинается с http://localhost:3000/s3/artwork-excerpts/, ответ 200. Рядом/дополнительным кадром можно показать исходный imageUrl из ответа API с localhost:9000 и тем же именем. Сохранять полностью видимым латинское имя, сгенерированное сервером.

## Проверка после показа

Вернуть citation_count записи 1 к исходному значению. Нажать «Выход» и проверить сброс фильтра. Базовые записи не удалять; удаление показывать на своей новой карточке.
