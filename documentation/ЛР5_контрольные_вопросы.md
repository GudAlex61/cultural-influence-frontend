# Ответы к защите ЛР5

1. **React** — библиотека декларативного интерфейса. При изменении состояния React
   повторно вызывает компоненты, сравнивает деревья элементов и обновляет нужные
   части DOM. В работе карточка — ArtworkExcerptCard, её данные приходят через props.
2. **Компонент и элемент**. Компонент — функция, возвращающая JSX; элемент —
   объект-описание конкретного узла интерфейса, например <ArtworkExcerptCard
   excerpt={excerpt} />. JSX преобразуется в вызовы jsx/jsxs, а не в строку HTML.
3. **Props** — входные данные для чтения. Фильтр получает artworkCreationDate,
   onDateChange, onApply, onReset. Дочерний компонент вызывает callback, а состояние
   изменяет родитель. Props нельзя непосредственно менять.
4. **State** — память экземпляра компонента между рендерами. В App две даты:
   вводимая и применённая. `setAppliedArtworkDate(artworkCreationDate)` вызывается
   кнопкой «Найти». Мутация обычной переменной не запустит рендер.
5. **useState** возвращает текущее состояние и setter. Setter планирует рендер;
   новое значение доступно на следующем рендере. Для обновления на основе
   предыдущего состояния можно писать `setDescriptionExpanded(previous => !previous)`.
6. **useEffect** синхронизирует компонент с внешней системой после commit.
   В ленте эффект меняет document.title и сбрасывает описание при смене ID.
   Cleanup восстанавливает title при размонтировании или перед следующим эффектом.
   [] — после первого монтирования; [id] — при монтировании и изменении id;
   без массива — после каждого commit. В StrictMode разработка дополнительно
   выполняет setup/cleanup эффекта для обнаружения ошибок. Это не production-поведение.
7. **Жизненный цикл**: монтирование → обновления props/state → размонтирование.
   Рендер должен быть чистым. Эффекты и их cleanup обрабатывают внешние действия.
   key={excerpt.id} пересоздаёт медиа при переходе, сбрасывая признаки ошибки.
8. **Vite** — сервер разработки и инструмент сборки. В разработке отдаёт модули
   через ES modules с HMR, при build формирует production-ресурсы в dist.
   **Babel** — преобразователь JS/JSX с плагинами, не сервер и не браузер.
   @vitejs/plugin-react обеспечивает интеграцию React и Fast Refresh;
   TypeScript проверяет `tsc -b`, Vite сам по себе проверку типов не заменяет.
9. **Фильтр**: controlled input type=date → onDateChange → useState родителя →
   submit/preventDefault → onApply → точное сравнение mock.artworkCreationDate.
   Пустой результат остаётся пустым. «Сбросить» очищает обе даты.
10. **Маршруты**: BrowserRouter использует History API; Link/useNavigate меняют
    URL без загрузки новой HTML-страницы. useParams читает :id, useLocation — путь.
    На сервере production нужен fallback index.html для прямых ссылок.
11. **Дефолтные медиа**: пустая/null-ссылка заменяется локальным SVG или MP4;
    onError также обрабатывает неработающий URL. Заглушка доступна без MinIO.
    Плитка не создаёт video, лента создаёт только текущее видео.
12. **Network**: в ЛР5 карточки импортированы из mock.ts, поэтому fetch/XHR к API
    нет. Есть запросы Vite к модулям и локальным медиа; HMR использует WebSocket.
    Переход Link не вызывает повторный запрос документа.

Источники: https://react.dev/learn и https://github.com/iu5git/Web/blob/main/tutorials/lab5/README.md
