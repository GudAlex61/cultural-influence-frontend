# Контрольные вопросы ЛР6

## Как устроен Redux Toolkit в проекте

Компонент вызывает dispatch. Для HTTP-операций с отрывками thunk запускает запрос
и отправляет pending, затем fulfilled или rejected. Reducer обновляет состояние в store,
а useSelector подписывает компонент на нужные данные. Сетевой запрос не выполняется в reducer.
`configureStore` подключает thunk middleware по умолчанию. Immer позволяет писать изменения
внутри createSlice привычным синтаксисом, сохраняя неизменяемость состояния Redux.

Store: `src/store/index.ts`. Два reducer: `auth` и `artworkExcerpts`.
Фильтры, текущий отрывок, черновик, загрузка и ошибка находятся в artworkExcerpts.
Пользователь, загрузка входа и ошибка входа находятся в auth. Пароля там нет.

Пример из проекта:

```ts
const dispatch = useArtworkDispatch();
const date = useArtworkSelector((s) => s.artworkExcerpts.filterDate);
void dispatch(loadArtworkExcerpts());
```

В loadArtworkExcerpts вызывается
`artworkApi.artworkExcerpts.artworkExcerptsControllerGetPublished(...)`.
Этот метод сгенерирован из Swagger и внутри использует Axios.

## Axios и fetch

Оба отправляют HTTP-запросы. Axios — библиотека с экземплярами клиентов, настройками,
interceptors и автоматическим преобразованием JSON. Обычно отклоняет Promise при не-2xx;
у fetch ответ 404 сам по себе не отклоняет Promise, требуется проверка response.ok.
В проекте домен отрывков использует сгенерированный Axios-клиент внутри thunk.
Вход и выход — отдельный обычный Axios и ручной dispatch, как требует задание.

## Cookie и localStorage

localStorage хранит строки на origin и сохраняется после перезапуска браузера;
JavaScript может его читать. Cookie браузер отправляет в подходящих HTTP-запросах автоматически.
HttpOnly-cookie недоступна JavaScript, но видна в Application браузера.
В нашей работе localStorage для авторизации не используется. Идентификатор сессии находится
в HttpOnly-cookie sessionId, соответствие пользователю и срок жизни — в Redis.
После F5 новый store гостевой, cookie при этом остаётся. Это специально требуется при показе.
«Выход» удаляет сессию на сервере и сбрасывает Redux с фильтром.

## CORS и обратный прокси

Origin — сочетание схемы, хоста и порта. CORS — политика браузера для чтения ответов
с другого origin; это не механизм авторизации. Обратный прокси принимает запрос клиента
и передаёт его внутреннему сервису. У нас браузер работает с localhost:3000:
/api проксируется на NestJS:3002, /s3 на MinIO:9000 с удалением префикса /s3.
Браузеру не нужно обращаться к другому origin. На production нужны аналогичные маршруты
в сервере размещения; dev-прокси Vite сам по себе production-инфраструктурой не является.

## BFF и GraphQL

BFF — отдельный backend, адаптированный под конкретный frontend; может объединять ответы
нескольких сервисов и скрывать их детали. GraphQL — язык запросов и среда выполнения API,
где клиент выбирает поля из типизированной схемы. Это разные понятия, их можно сочетать.
Наша работа использует REST API NestJS, BFF и GraphQL не реализованы.

## Next.js и SSG

Next.js — React-фреймворк с маршрутизацией и серверными возможностями, включая SSR и SSG.
SSR формирует страницу на запрос, SSG создаёт HTML заранее при сборке либо регенерации.
Наш проект — клиентское SPA на Vite с React Router; данные запрашиваются после загрузки.
Next.js и SSG здесь не используются.

## FSD

Feature-Sliced Design разделяет frontend по слоям и бизнес-срезам: app, pages, widgets,
features, entities, shared. Зависимости направлены к нижним слоям, публичный API среза
ограничивает доступ к его внутренностям. В работе используется простая структура pages,
components, api и store; полной реализацией FSD её называть не нужно.

## Что добавилось в ЛР6

Четыре работающих окна вместо гостевого mock-интерфейса: вход/регистрация,
получение данных сервера, фото и видео в MinIO, черновик и публикация, лайк и удаление
своей записи. Redux хранит фильтр и состояние пользователя, Axios-клиент генерируется
из Swagger. При недоступном сервисе только гость получает mock; блокирующая анимация
показывает выполнение запросов. Защита владения и сессии проверяется сервером.
